Rules

Each rule is one requirement on a learning app. It lives where it acts: as a section of a skill for AI assistants, as a check, as a lint rule or as an item of the review rubric. The same rule can live in several of them, always under the same id. This page reads them from there.

  • Scope: listing applies to every app in the app overview, however it is built and wherever it is hosted; tooling to apps built with this tooling (their package.json lists @lernapps/tooling), because the rule presupposes its plan workflow or its checks, and to them in the app overview too; archetype:… to apps of that archetype.
  • Severity: error must not be broken; warning only with a reason recorded in place; hint is a recommendation.

Every message of a check links to its rule here, by its id: https://lernapps.net/tooling/rules/#<id>.

Accessible to WCAG 2.1 AA

accessible · listing · error

Meet WCAG 2.1 AA: labels, contrast, keyboard use, text alternatives. Only where the app's idea needs it (a typing game against the clock) may it deviate: then say in plain German what it does not offer in the entry's field limits, which teachers and parents read in the catalog. With limits in the entry, lernapps check --entry reports this rule's findings as warnings; without it, as errors.

Told in the skill skills/lernapps-app/references/platform-rules.md; checked by the check check/rules/accessible.ts.

The published app can be opened and checked

app-checkable · listing · error

The app opens at the entry's url, so that lernapps check can visit its pages; a built app opens from its bundle (index.html). An app that cannot be opened cannot be checked, and learners cannot use it either. When the page does not load, the app's build fails, no browser can start or the check stops, the checks report this rule instead of the others. Fix the app so that it opens at the entry's url, then check again. When the app opens in a browser but the check itself fails, open an issue at https://github.com/lernapps/tooling/issues with the message.

Told in the skill skills/lernapps-app/references/platform-rules.md.

Help keep the content correct

correct-content-support · listing · hint

Where answers are computable, generate the exercises and test the answers with a checker. Name a source learners and teachers can follow for facts. This should be done where it fits; it is never a condition for listing.

Told in the skill skills/lernapps-app/references/platform-rules.md; judged by the rubric item in review/rubric.md.

Only dependencies with an open licence

dependency-licence · listing · error

Add a package to dependencies only if it and its own dependencies have one of these licences: MIT, MIT-0, ISC, 0BSD, BSD-2-Clause, BSD-3-Clause, Apache-2.0, MPL-2.0, BlueOak-1.0.0, Zlib, Unlicense, CC0-1.0, CC-BY-4.0, Python-2.0. Tools for the build belong in devDependencies.

Told in the skill skills/lernapps-app/references/platform-rules.md; checked by the check check/rules/dependency-licence.ts.

Fitness values as measured

entry-fitness-matches · listing · error

Take fitness.storage and fitness.thirdParty from what the app does, not from what it should do: lernapps check --report <file> measures what it does before a click. An app that keeps anything in localStorage has storage: device; one that loads from another server after a click has thirdParty: on-click.

Told in the skill skills/lernapps-app/references/platform-rules.md; checked by the check check/rules/entry-fitness-matches.ts.

Fill the entry from the published schema

entry-from-schema · listing · error

Fetch the entry schema each time you need it; never fill the entry from memory or from another app. Take every value from the creator's answers, the plan or the app; never invent one.

Told in the skill skills/lernapps-app/references/platform-rules.md.

Every link of the entry resolves

entry-links-resolve · listing · error

Give each topic the path of a page that exists, relative to the app's url; a topic that links a section of a page (<page>#<section>) names the id of an element on that page. Check the entry against the deployed app with lernapps check --entry <file>.

Told in the skill skills/lernapps-app/references/platform-rules.md; checked by the check check/rules/entry-links-resolve.ts.

Free of charge

free-of-charge · listing · error

Every part of the app is free: no payment, no paid upgrade, no trial that ends.

Told in the skill skills/lernapps-app/references/platform-rules.md; judged by the rubric item in review/rubric.md.

German always, every declared language complete

learner-text-german · listing · error

Write every text for learners, teachers and parents in German, in plain language: short sentences, active voice, no jargon. German is always there. An app may add further languages where its archetype supports them (the explainer and the quiz: languages, German first); then every text is complete in each declared language, and in no other. Keep the texts out of code: in the content of a deep archetype (an explainer's YAML, a quiz's question bank), or in message files, e.g. src/messages/de.json, shown with translator from @lernapps/tooling/i18n.

Told in the skill skills/lernapps-app/references/platform-rules.md; checked by the lint rule lint/rules/learner-text-german.ts; judged by the rubric item in review/rubric.md.

learners-act · listing · error

Told in the skill skills/lernapps-app/references/platform-rules.md; judged by the rubric item in review/rubric.md.

No ads

no-ads · listing · error

Nothing about a particular learner in public texts

no-learner-data-in-texts · listing · error

Write no name, class, school, grade, picture or other detail of a real learner into the app, the entry, the README, the plan or a commit message, even when the creator mentions one. Use made-up names in exercises.

Told in the skill skills/lernapps-app/references/platform-rules.md; judged by the rubric item in review/rubric.md.

No request to another server before a click

no-request-before-click · listing · error

Bundle fonts, scripts and pictures at build time. Load anything from another server (a video, a map) only after the learner clicks for it. Keep URLs of other servers out of code; where the learner clicks to load one, suppress the lint message on that line with this reason.

Told in the skill skills/lernapps-app/references/platform-rules.md; checked by the check check/rules/no-request-before-click.ts; checked by the lint rule lint/rules/no-request-before-click.ts.

Collect nothing, set no cookies

no-tracking · listing · error

No cookies, no analytics, no tracking pixels, no server that stores data. If the app stores anything, it stays on the device (localStorage) and serves only the app.

Told in the skill skills/lernapps-app/references/platform-rules.md; checked by the check check/rules/no-tracking.ts; judged by the rubric item in review/rubric.md.

Every page is reachable from the start page

pages-reachable · listing · error

Link every page the build writes from the start page or from a page it leads to: learners find only what links reach, and the checks of the listing, which open the app at its address, check only those pages. Leave pages nobody should reach out of the build. A page reached another way on purpose gets <meta name="robots" content="noindex">; a 404.html at the root is the host's page for addresses that do not exist and needs no link. On a URL the checks visit at most 100 pages; a hint then says so: check the bundle to check every page.

Told in the skill skills/lernapps-app/references/platform-rules.md; checked by the check check/rules/pages-reachable.ts.

Runs in the browser, without installation

runs-in-browser · listing · error

The app opens at its URL in a current browser and works there. Nothing to install: no app store, no download, no browser extension.

Told in the skill skills/lernapps-app/references/platform-rules.md; judged by the rubric item in review/rubric.md.

Name source and licence of others' content

third-party-licence · listing · error

Use content of others (texts, pictures, quotes) only with a licence that allows it, and name source and licence next to it.

Told in the skill skills/lernapps-app/references/platform-rules.md; judged by the rubric item in review/rubric.md.

Usable at 360 px

usable-at-360px · listing · error

Every page works at 360 px width without horizontal scrolling, with every control reachable. Only where the app's idea needs it (a keyboard is required) may it deviate, said in the entry's field limits as under accessible; with it, lernapps check --entry reports this rule's findings as warnings, without it as errors.

Told in the skill skills/lernapps-app/references/platform-rules.md; checked by the check check/rules/usable-at-360px.ts.

Keep the app's content guide

app-content-guide · tooling · error

Keep .agents/skills/app-content/SKILL.md with its fixed headings. Fill in every placeholder ("FILL IN") once the creator has confirmed the plan, before you build the content, with precise, concrete instructions: the files, ids, data files and an example of this app, not general advice. Whenever a content decision changes (a new pattern, a figure type, a source rule), change the guide in the same commit. The plan file records one run; the guide is what the agents after you follow. lernapps check checks an app from the generator: the file and its headings always, and that no placeholder is left once the app has content, which is when its plan is in Commit: by then the creator's questions (quiz) or chapters (explainer) are built in place of the generated example. An app made before the guide existed gets its skeleton from npx --yes github:lernapps/tooling#main update.

Told in the skill skills/lernapps-app/references/workflow-rules.md; checked by the check check/rules/app-content-guide.ts.

The content guide says what was built

app-content-matches · tooling · error

The guide describes the app as it is: every exercise pattern it names is used, and the app uses no pattern it does not name; the curriculum, the competencies and their chapters, pages or rounds match the content; the procedure for a new chapter or round names the files as they are now. Write it so that an agent who never saw your conversation can add the next chapter or round from it alone.

Told in the skill skills/lernapps-app/references/workflow-rules.md; judged by the rubric item in review/rubric.md.

Run the checks before you push

checks-pass · tooling · error

Run lernapps check before you push; the hooks run it too. Format, lint, type check, unit tests, build, the checks of the built app and the end-to-end tests must pass. A failure names the step: fix it from the step's output. CI runs the same command and nothing else, so what passes on your machine passes in CI. A failed CI run has the same message as the hook, and its report is the artifact validation-report.

A test that comes with the archetype's runtime (@lernapps/app-templates) and fails while your content validates is a bug in the template; the message names it as a test of the template. Tell the creator, and open an issue at https://github.com/lernapps/app-templates/issues with the validation report (node_modules/.cache/lernapps/validation-report.yaml), or ask the creator to. Never change the tests or the configuration to get around it. The app pins the runtime to a commit, so npm update changes nothing; once the fix is in, npx --yes github:lernapps/tooling#main update moves the app to it. Then run npx lernapps check and commit.

A link whose server limits requests (HTTP 429) is reported as not checked, at severity hint: it fails nothing. Tell the creator which links could not be checked, and go on.

Told in the skill skills/lernapps-app/references/tooling-rules.md.

No code before the plan is confirmed

explore-before-code · tooling · error

Write no code and generate nothing until the creator has confirmed the plan.

Told in the skill skills/lernapps-app/references/workflow-rules.md.

Work on your own after the plan

few-turns-after-plan · tooling · hint

After the plan is confirmed, ask the creator only what you cannot decide. Otherwise choose, mark it "(guess)" under "Key decisions" and list it in the retrospective.

Told in the skill skills/lernapps-app/references/workflow-rules.md.

Fix failed checks, never bypass them

fix-from-message · tooling · error

Read the message of a failed check and fix the cause. A failed commit prints one line with the step and the log node_modules/.cache/lernapps/pre-commit.log: the messages are in that log. Never bypass a hook (--no-verify), never delete a test to make it pass.

Told in the skill skills/lernapps-app/references/tooling-rules.md.

Keep the plan file

plan-file · tooling · error

Keep each plan in .vibe/plans/ as its template has it, with every section and front matter key; never change the plan of an earlier piece of work. Update phase when you enter a phase. Never edit prePushFailures: the pre-push hook writes it.

Told in the skill skills/lernapps-app/references/workflow-rules.md; judged by the rubric item in review/rubric.md.

Fill the retrospective

retrospective-filled · tooling · error

At the end of Commit, fill every part of the retrospective with facts: phases reached, failed checks with rule ids, the creator's turns after the plan, where you had to guess. No names of people.

Told in the skill skills/lernapps-app/references/workflow-rules.md; judged by the rubric item in review/rubric.md.

Stop at the creator's checkpoints

stop-at-checkpoints · tooling · error

Stop at each checkpoint (research, confirm the plan and the content method, publish, list) and wait for the creator's answer. Example: "Die App ist fertig und geprüft. Soll ich sie jetzt veröffentlichen?"

Told in the skill skills/lernapps-app/references/workflow-rules.md.

Suppress only in place, with the reason

suppression-reason · tooling · error

Suppress a lint message only on the line where it occurs, name the rule and write why after --: // oxlint-disable-next-line lernapps/no-request-before-click -- the video loads after a click. Suppress a type error only with // @ts-expect-error -- <reason>, never with @ts-ignore or @ts-nocheck. The review reads every suppression.

Told in the skill skills/lernapps-app/references/tooling-rules.md; checked by the lint rule lint/rules/suppression-reason.ts.

The content validates

explainer-content-valid · archetype:explainer · error

Every file validates against the schema, every id is unique on its level, every reference (a data file, an image, a component, a link to a page or section) exists, every placeholder is declared and every formula uses only the command list. The build names each problem in one line with file, line and block path; fix it there.

Told in the skill skills/lernapps-explainer/SKILL.md.

explainer-figure-explains · archetype:explainer · hint

Formulas as formulas

The property test passes

explainer-generated-sound · archetype:explainer · error

Write given and where so that where holds often, the answer is defined and in its format for every draw, and no mistake can equal it. When the property test fails, it names the seed: narrow given or change the mistake, never the comparator to make it pass.

German first, every language complete

explainer-languages · archetype:explainer · error

Typical mistakes with their message

explainer-mistakes-diagnosed · archetype:explainer · hint

Every page in one chain

explainer-navigation · archetype:explainer · error

Leave the navigation to the runtime: contents, breadcrumbs and previous and next follow from the order lists, so every page is in one chain and reachable from the start page. Link from prose with paths that start at the app's root. lernapps check finds a page no link from the start page reaches (pages-reachable), and a topic of the entry whose #<section> is no section of its page (entry-links-resolve).

Told in the skill skills/lernapps-explainer/SKILL.md.

Write only the content

explainer-only-content · archetype:explainer · error

Write the YAML of the app, its chapters, pages and data, the bundled images in src/images/, and components with their logic and tests in src/components/. Keep src/main.ts, index.html, e2e/explainer.e2e.ts and the configuration as generated (keep-the-preset). The build fails on any other file in src/. The description and the playthroughs validate

interactive-app-valid · archetype:interactive · error

src/app.yaml and every playthrough validate against their schemas. German comes first and every declared language is complete. Ids are unique, there is at least one playthrough, each step expects a state or an announcement, and a playthrough's route is one of the app's. The build names each problem in one line with file and line; fix it there.

Told in the skill skills/lernapps-interactive/SKILL.md.

The architecture is valid and current

interactive-architecture-current · archetype:interactive · error

docs/arc42/ holds the generic part and the interactive extension as lernapps create or lernapps update wrote them, unchanged outside the app sections, and the app's own part inside them describes the code as it is: every part of src/ has its block, every block its code. arc42 validate --strict in lernapps check and arc42 diff --staged --strict before a commit pass; the review reads whether the architecture still says what the code does.

Told in the skill skills/lernapps-interactive/SKILL.md; judged by the rubric item in review/archetypes/interactive.md.

The core keeps its contract

interactive-core-contract · archetype:interactive · error

src/core/index.ts exports start(seed, route) and step(state, input), and tick(state, dt) as a function when the app moves on its own. Every route starts, nothing throws, and the same seed, route, inputs and ticks give the same states.

Told in the skill skills/lernapps-interactive/SKILL.md.

Every playthrough plays as written

interactive-playthroughs-pass · archetype:interactive · error

After each step of a playthrough, the core's state has the fields the step expects. The browser shows the announcement it expects. When one fails, fix the core or the playthrough, whichever is wrong; never delete a playthrough to make the build pass.

Told in the skill skills/lernapps-interactive/SKILL.md.

Extend the preset, change nothing of it

keep-the-preset · archetype:explainer, archetype:interactive, archetype:quiz · error

An app from an archetype extends the preset of @lernapps/tooling and configures nothing the preset sets: vite.config.ts is export default lernapps(), tsconfig.json extends @lernapps/tooling/tsconfig.json as generated, the hooks come from the package (prepare in package.json). Pass only the app's own settings to lernapps({ ... }), such as the pages to build or the build step of its archetype's runtime, as generated: lernapps({ plugins: [quiz()] }). Never turn a lint rule off or lower its severity, never replace a hook.

Told in the skill skills/lernapps-app/references/tooling-rules.md.

Publish from gh-pages, served from its root

pages-from-gh-pages · archetype:explainer, archetype:interactive, archetype:quiz · error

An app from the generator publishes with the app publish action: GitHub Pages of the app repo serves the branch gh-pages from its root (/), at the repo's Pages address (usually https://<owner>.github.io/<repo>/; only a repo of the lernapps organisation is served at https://lernapps.net/<repo>/). Previews of pull requests will go below pr-preview/ on the same branch, so leave that setting as it is. When the publish run fails, read its message: fix what you can, and tell the creator the exact clicks it names for what only a repository admin may change. The creator may host the app elsewhere; then the entry's url points there.

Told in the skill skills/lernapps-app/references/tooling-rules.md.

A component only where no block fits

prefer-built-in-block · archetype:explainer · hint

quiz-answers-checked · archetype:quiz · hint

Where you cannot open a source, say so in the plan and mark the fact as not checked; never fill a gap from memory. Learners report errors through the issue form the generator wrote (.github/ISSUE_TEMPLATE/inhaltsfehler.yml).

The question bank validates

quiz-bank-valid · archetype:quiz, archetype:explainer · error

The bank validates against its schema. The build also checks what the schema cannot say: - exactly one correct option in a single choice, at least one in a multiple choice; - ids and options that appear only once.

A broken bank fails the build with one line per problem, naming the question by its position and id. Fix each one in src/quiz.json. A quiz-type exercise of an explainer validates the same way, named by its file and block path.

Told in the skill skills/lernapps-quiz/SKILL.md.

One clear question at a time

quiz-clear-question · archetype:quiz, archetype:explainer · warning

Ask one thing per question, complete in itself: the learner knows what to answer before reading the options. Ask positively; avoid "nicht" in the question, and never two negations. No trick questions: ask what is worth knowing, not whether the learner reads carefully. Plain language and short sentences, in German and in every other language of the quiz (learner-text-german).

Told in the skill skills/lernapps-quiz/SKILL.md.

Background and explanation say why

quiz-feedback-explains · archetype:quiz, archetype:explainer · hint

Give every option an info of one to three sentences about the option itself. It must be true whether or not the option is the right answer, so that a learner who chose it learns something real. Example: "Der Nil fließt durch mehrere Länder Afrikas und mündet in Ägypten ins Mittelmeer." The explanation says in one to three sentences why the right answer is right. For true/false, number, ordering and matching it also carries the background. For a wrong option, say in its info why it does not fit: a learner who chose it reads it as the reason. Give a number question its typical wrong numbers as mistakes (answer, message), and any question an optional hint that points to where to look without giving the answer away.

Told in the skill skills/lernapps-quiz/SKILL.md; judged by the rubric item in review/archetypes/quiz.md.

The type that fits the question

quiz-fitting-type · archetype:quiz, archetype:explainer · hint

Choose the type from what the learner should do: - recall one fact out of several things of the same kind: single-choice; - several facts: multiple-choice; - estimate a size: number; - compare sizes or dates: ordering; - connect things that belong together: matching; - judge a statement: true-false.

Mix types across the quiz. Choose a type that accepts every answer the text allows: an ordering only where the order is fixed (skill lernapps-exercise-patterns, "How an exercise checks success").

Told in the skill skills/lernapps-quiz/SKILL.md.

Every question links to further reading

quiz-further-reading · archetype:quiz · warning

Link every question to at least one page where learners read on, best the article in the German Wikipedia (https://de.wikipedia.org/wiki/...). Read every linked page before you commit: - it is the article you mean, not a disambiguation page ("Begriffsklärung"); - it says what your question and options say.

Leave resolving links to lernapps check: it checks the app's own links and the entry's, and reading an article shows that its link resolves. Write no scraper, script or API loop that fetches pages for you. When a site limits your requests (HTTP 429), tell the creator which links you could not read, mark those facts as not checked in the plan, and go on.

Name the page in the link's title, e.g. "Uluru (Wikipedia)". Never guess an address.

Told in the skill skills/lernapps-quiz/SKILL.md.

Numbers with unit and rounding

quiz-number-precision · archetype:quiz, archetype:explainer · warning

A number question says in its text how exactly to answer, e.g. "Bis zu 100 m daneben zählt noch als richtig". It names the unit in unit, not in the learner's answer. Match tolerance to what the text says. Where sources differ (the height of a mountain), choose a tolerance that covers them.

Write in your own words

quiz-own-words · archetype:quiz · warning

Take facts from your sources, never their sentences. Wikipedia's texts are under CC BY-SA, so a copied sentence needs attribution and puts the app's texts under the same licence. Write each info and explanation new, shorter and plainer than the source, for learners of the school year the app is for. Facts themselves are free to use; name where they come from in sources (third-party-licence).

Options a learner could believe

quiz-plausible-options · archetype:quiz, archetype:explainer · warning

Make every wrong option a real thing of the same kind as the right one: a river for a river, a mountain for a mountain. A learner could mix it up, and it has true background of its own. Make all options alike in length and form, so that the right one does not stand out. No "Alle genannten" or "Keine davon", no joke options. Three or four options are enough.

Store only through the preset's storage

storage-through-wrapper · archetype:explainer, archetype:interactive, archetype:quiz · error

Keep what the app must remember with createStorage from @lernapps/tooling/storage, named after the app: it stays on the device, under the app's own prefix, and the app keeps working when the browser blocks storage. All apps share the origin's localStorage, so an app keeps at most 100 kB under its prefix (keys and values, 2 bytes per UTF-16 code unit): save returns false beyond it, as when storage is blocked, and the app keeps working. Keep the learning state, not histories that keep growing. Never use localStorage, sessionStorage, IndexedDB or cookies directly.

Told in the skill skills/lernapps-app/references/tooling-rules.md; checked by the lint rule lint/rules/storage-through-wrapper.ts.

An exercise component has its logic module

vue-component-exercise-contract · archetype:explainer · error

When a component emits answered, put its logic into src/components/<Name>.ts with generate(seed, props), check(task, answer), solution(task) and wrong(task), pure and deterministic, so that the build's property test passes. Its block lists examples with at least one accepted and one rejected answer, { answer, seed? } in the shape check takes (without a seed, for the tasks of seeds 1 to 50), including another correct answer where the text allows one.

It declares the prop seed: number and shows generate(seed, props): the explainer gives the seed, shows "Aufgabe Nr." and "Neue Aufgabe" and keeps ?<id>=<n> in the address; never draw a seed or offer a "next" button inside the component. Its logic module also exports describe(task, props, lang), giving { task, solution } in restricted Markdown, the task exactly as the learner sees it, and about = { task, answer, correct, mistakes }, texts by language: what the learner does, the answer format, what counts as right, the typical mistakes. A tutor reads only these: the build writes them into the page's tutor.md and the component's text without JavaScript.

Any exercise may carry examples: { accepted, rejected }, which the build checks and learners never see; for generated they are expressions of given and answer, checked for every seed (e.g. reverse(answer)).

Told in the skill skills/lernapps-explainer/SKILL.md.
