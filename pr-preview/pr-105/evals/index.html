Eval results

The evals test an assistant configuration (harness, its version, model) on our guidance: does the creator's assistant follow it from the creator's first prompt to the publish checkpoint? A simulated creator answers from a persona. A verifier scores the app folder at the end (plan, app, git), a second script scores the transcript. These are the first results.

Data of 2026-10-18 (runs 2026-10-17 23:13 to 2026-10-18 05:59 UTC) · 33 runs · claude-code 2.1.302 · Harbor 0.24.0 · creator played by Haiku 5.5 · guidance 7ceb8c4 · data.json

Bottom line

  • Sonnet 5.5 and Opus 5.5 follow the process nearly fully on all three archetypes.
  • Haiku 5.5 builds apps that pass the check every time, but skips process steps: the content guide stays empty in 12 of 14 runs.
  • Opus 5.5 is not better than Sonnet 5.5 and takes up to 2.5 times as long.
  • No configuration keeps to one or two questions per turn.

How to run an eval

evals/harbor/setup.sh
evals/harbor/run.sh quiz-fresh anthropic/<model> 3
node evals/summary.ts ~/.lernapps-evals/jobs

Setup once per machine, one job per task and model, then the summary. Details at the end of this page.

Findings

  • Sonnet 5.5 and Opus 5.5 wrote the competencies, filled the content guide, chose the right archetype, passed the check, reached the commit phase and committed clean in every run, with one exception: Opus 5.5 left the content guide empty in 1 of 2 interactive runs. They ticked 93–100 % of the plan's boxes on average.
  • Haiku 5.5 passed the check in 14 of 14 runs, but:
    • filled the content guide (app-content) in only 2 of 14 runs;
    • ticked between 0 and 100 % of the plan's boxes per run (mean 70 % quiz, 46 % explainer, 7 % interactive);
    • wrote no competencies ("Ich kann …") in any of the 3 interactive runs, and in 9 of 14 runs overall;
    • chose the wrong archetype once: an explainer for the typing trainer;
    • created the app before the creator confirmed the plan in 3 runs, one per archetype;
    • needed more creator turns after the plan on the explainer (mean 3.8) and the interactive app (4.0) than Sonnet and Opus (2 to 3); on the quiz it needed fewer (1.5);
    • stopped in the code phase in 2 of 5 explainer runs.
  • Questions: 32 of 33 runs asked more than two questions in one turn. Haiku 5.5 asked at most 2–7, Sonnet 5.5 4–8, Opus 5.5 4–12. The score counts sentences that end in "?" in the agent's text, so questions inside a plan draft count too.
  • Time and cost: Opus 5.5 took 60 minutes on the explainer against 24 for Sonnet 5.5 (2.5 times), 41 against 21 on the interactive app, 24 against 20 on the quiz, and read 3.5 times as many cached tokens on the explainer. Haiku 5.5 was faster only on the quiz (15 minutes).
  • Reading the guidance: every run fetched guidance through a summarising fetch tool at least once; 32 of 33 also downloaded the plan template and read it word for word.

What it may mean for the guidance

Candidates, not decisions:

  • Enforce the content guide: a check or hook that fails while "FILL IN" is left in .agents/skills/app-content/SKILL.md.
  • Make the choice of archetype clearer for the interactive case (a typing game is interactive, not an explainer).
  • Make the plan confirmation a checkpoint before create that is hard to miss.
  • Rethink the rule of one or two questions per turn: no model keeps it today. State it more plainly, or count it differently.

Next: guidance for agents, not for humans

The goal of the evals is to optimise the guidance for agents. Today the plan template, the skills and the rules are long and written as prose for people. The hypothesis: a much more compact variant (bullet points, less boilerplate, nothing written only for humans) gives similarly good conversations at a much lower cost.

How the evals will test it: the same scenarios and configurations, with a compact variant of the guidance as the only change. Then compare the quality dimensions above and the cost: agent tokens, creator turns and minutes. Today's numbers are the baseline:

How we got here

Since the evening of 17 October 2026; times are local (CEST).

  1. 22:16 Inventory of the guidance as a chain (build prompt → llms.txt → skill → plan → archetype skill → tool messages → listing) and the expectations A1–A34, each with its evidence.
  2. 22:25 ADR with a three-point Pugh matrix (−1, 0, +1 against plain scripts) over six options: scripts and result files, Claude Code's plugin eval, Inspect, Harbor, promptfoo, an own container. First result: scripts and Harbor tied.
  3. evening A spike without a model: Harbor 0.24.0 runs in the cloud container, with Docker started by hand, the proxy's CA baked into every image and base images from a mirror registry.
  4. evening Credentials: the platform filters environment variables named ANTHROPIC_*, so the key is stored as EVALS_ANTHROPIC_API_KEY. A subscription token worked, but with Harbor's ACP bridge it did not reach the agent under test. A small local patch fixes it; it is reported upstream.
  5. evening First real run: a quiz mini-task on Haiku, 2 turns, under 2 minutes.
  6. 01:02 ADR accepted: Harbor, the only option with a simulated creator; +2 against 0 for the scripts after the spike.
  7. 01:13 The matrix starts: three lanes in parallel overnight. No new runs after 07:00, before the subscription's usage window reset; the last run ended at 07:59.
  8. during the night Fixes found while running: Harbor's .acpxrc.json in the app folder made lernapps create refuse it, so it moved to the global config. The persona stopped at a GitHub Pages question in Explore; now it stops only at the real publish checkpoint (one run excluded, see below). The transcript score raised false hook-bypass alarms; now only real bypasses count. The retrospective became n/a for runs that stop before the listing.

Limits

  • Small n: 2 to 6 runs per cell. One creator model (Haiku 5.5), one guidance commit.
  • Fresh scenarios only: no increment, no prepared start states yet.
  • GitHub only as a local remote in the container; the GitHub cases on github.com are not run yet.
  • Claude Code only; Codex and Gemini CLI are not run yet.
  • Harbor's own token and cost numbers are wrong for the agent behind the ACP bridge; the tokens here are summed from the agent's session log.
  • Excluded: one interactive run with Haiku 5.5. The persona took a GitHub Pages question in Explore for the publish checkpoint and ended before the plan, a fault of the harness, not of the agent (fixed since).

How to run it, in detail

What it needs

  • A machine with Docker (the daemon is started by setup.sh if none runs), uv and Node 22. In a Claude Code cloud container this is all there.
  • A credential in EVALS_ANTHROPIC_API_KEY: an API key, or a subscription token from claude setup-token. In a cloud environment, store it as an environment variable under that name; names starting with ANTHROPIC_ are filtered out by the platform.
  • About 2 GB of disk for the task image and up to 1.5 GB per running trial.

Steps

  1. evals/harbor/setup.sh installs Harbor 0.24.0 into ~/.lernapps-evals, applies the patches in evals/harbor/ (the subscription token for the ACP bridge, the acpx config outside the app folder) and writes the generated files into each task.
  2. evals/harbor/run.sh <task> <model> [trials] [concurrency] runs one Harbor job. The tasks are quiz-fresh, explainer-fresh and interactive-fresh; the model is a Harbor name such as anthropic/claude-sonnet-5-5; USER_MODEL sets the simulated creator (default: the same model). Harbor runs through evals/harbor/harbor.sh, which clears the environment, so no other credential reaches the containers. The job lands in ~/.lernapps-evals/jobs with its configuration.json and the transcript score.
  3. For a matrix, start one run.sh per model in parallel; two or three at a time fit a machine with 4 CPUs and 16 GB. Watch the rate_limit_event lines in <trial>/user-agent/claude-code.txt and stop at a limit.
  4. node evals/summary.ts ~/.lernapps-evals/jobs prints mean, min and max per dimension for each task and configuration; configurations are never mixed. A job with an excluded.txt (its reason inside) is left out.
  5. node evals/report.ts ~/.lernapps-evals/jobs writes site/evals/data.json and the tables and charts of this page.
