Rules

Each rule is one requirement on a learning app. It lives where it acts: as a section of a skill for AI assistants, as a check, as a lint rule or as an item of the review rubric. The same rule can live in several of them, always under the same id. This page reads them from there.

  • Scope: listing applies to every app in the app overview, however it is built and wherever it is hosted; tooling to apps built with this tooling (their package.json lists @lernapps/tooling), because the rule presupposes its plan workflow or its checks; archetype:… to apps of that archetype.
  • Severity: error must not be broken; warning only with a reason recorded in place; hint is a recommendation. A tooling rule never blocks a listing: in the listing validation and the review its findings are warnings at most, advice for the creator; in the app's repo its severity holds.

Every message of a check links to its rule here, by its id: https://lernapps.net/tooling/rules/#<id>.

Accessible to WCAG 2.1 AA

accessible · listing · error

  • WCAG 2.1 AA: labels, contrast, keyboard, text alternatives.
  • Deviate only where the idea needs it (typing game against the clock); then say what is missing, in plain German, in the entry's limits.
  • With limits: lernapps check --entry reports warnings; without: errors.

Told in skills/tooling/lernapps-cli/references/platform-rules.md; checked by the check check/rules/accessible.ts.

The published app can be opened and checked

app-checkable · listing · error

  • Opens at the entry's url; a built app from its bundle (index.html).
  • Page does not load, build fails, no browser, check stops → only this rule is reported. Fix, check again.
  • Opens in a browser but the check fails → issue at https://github.com/lernapps/tooling/issues with the message.

Told in skills/tooling/lernapps-cli/references/platform-rules.md.

Touch only the app's own data in the browser

own-data-only · listing · error

  • Every app on lernapps.net shares one origin with the other apps and the platform.
  • Own data: keys of localStorage and sessionStorage, IndexedDB databases and caches named lernapps:<id>:…, <id> the app's id in the catalog (entries/<id>.yaml).
  • Never read, write or remove other keys; never clear(); never caches.match() without cacheName.
  • Built with this tooling: createStorage("<id>") from @lernapps/tooling/storage.
  • lernapps check puts another app's data into the browser and reports every access to it, before a click.

Told in skills/tooling/lernapps-cli/references/platform-rules.md; checked by the check check/rules/own-data-only.ts; judged by the rubric item in review/rubric.md.

  • 404.html at the root needs no link.
  • On a URL the checks visit at most 100 pages (hint); check the bundle for all.

Told in skills/tooling/lernapps-cli/references/platform-rules.md; checked by the check check/rules/pages-reachable.ts.

Keep the app's content guide

  • Keep .agents/skills/app-content/SKILL.md with its fixed headings.

  • lernapps check checks the file and its headings always, and that no placeholder is left once the plan is in Commit.

An exercise component has its logic module

vue-component-exercise-contract · archetype:explainer · error

  • Emits answer → src/components/<Name>.ts with pure, deterministic generate(seed, props), check(task, answer), solution(task), wrong(task), reason(task, answer, props, lang); property test passes.
  • Emits no answered (the old contract): the explainer draws "Prüfen" and checks; a component draws none.
  • Block lists examples with at least one accepted and one rejected, { answer, seed? } in the shape of check (no seed: seeds 1–50), incl. another correct answer where the text allows.
  • Declares prop seed: number, shows generate(seed, props). The explainer gives the seed, shows "Aufgabe Nr.", "Neue Aufgabe", keeps ?<id>=<n>: never draw a seed or offer "next" inside.
  • Also exports describe(task, props, lang) → { task, solution } (restricted Markdown, task exactly as shown) and about = { task, answer, correct, mistakes } (texts by language). The tutor reads only these (the tutor page, no-JS text).
  • Any exercise may carry examples: { accepted, rejected }; generated: expressions of given and answer, per seed (e.g. reverse(answer)).
  • With template, params, mistakes and show (all four or none, rule vue-component-tutor-table): check accepts the solution and rejects each mistake's answer, params gives the same names for every task, each placeholder of template is one of them.
